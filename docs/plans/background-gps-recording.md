# Запись GPS-тренировки с выключенным экраном

Статус: реализация завершена; автоматические проверки и сценарии эмулятора пройдены.
Полевую проверку GPS и энергосбережения на телефоне предстоит выполнить отдельно.

## Цель и границы

Пользователь получает подходящий GPS-сигнал, запускает тренировку, блокирует
телефон, при необходимости ставит запись на паузу, продолжает и завершает её.
Приложение локально сохраняет длительность, измеренную дистанцию и GPS-трек.

В эту фичу входят:

- Старт только при готовности GPS и наличии разрешения на точную геопозицию.
- Запись независимо от экрана карты, переключения вкладок и выключения экрана.
- Пауза и продолжение из приложения и уведомления.
- Завершение из приложения без подтверждения.
- Сохранение незавершённой тренировки и восстановление после прерывания.
- Сохранение итоговой тренировки и появление её в существующем списке истории.

Экран просмотра сохранённого трека, расширенная статистика, редактирование,
экспорт и скачивание офлайн-карт не входят в эту фичу. Для будущего экрана
просмотра сохраняем данные так, чтобы маршрут и показатели были доступны без
интернета, а подложка карты оставалась необязательной.

## Согласованное поведение

| Сценарий | Поведение |
| --- | --- |
| Нет подходящей GPS-точки | Старт недоступен; отображается причина |
| GPS готов | Пользователь явно нажимает «Начать запись» |
| Экран выключен или открыта другая вкладка | Запись продолжается |
| Пауза | Время и перемещение исключаются из тренировки |
| Продолжение | Начинается новый сегмент; расстояние через паузу не добавляется |
| Потеря GPS | Время продолжается; новые точки и дистанция не добавляются |
| GPS восстановлен | Начинается новый сегмент без соединения через неизвестный участок |
| Завершение | Запись останавливается; результат сохраняется без подтверждения |
| Сохранение успешно | Экран возвращается в готовность; тренировка видна в истории |
| Ошибка сохранения | Запись остаётся остановленной; доступны ошибка и повтор сохранения |
| Сбой приложения или перезагрузка | При следующем открытии предлагается продолжить или завершить сохранённую незавершённую тренировку |
| Продолжение после прерывания | Требуется готовность GPS; создаётся новый сегмент; время и перемещение прерывания исключаются |

Приложение не начинает тренировку автоматически при появлении GPS, после
перезагрузки или после открытия незавершённой записи. Для возобновления требуется
действие пользователя.

## Исходное состояние проекта

- Route / Screen / ViewModel, Hilt, StateFlow и Navigation 3.
- Управление стартом, паузой и завершением в экране карты.
- Room со схемой v1 и таблицей итоговых тренировок.
- Локальная история тренировок и форматирование длительности и дистанции.
- Unit-тесты текущих переходов состояния и ViewModel.

До реализации таймер принадлежал MapViewModel, GPS-точки не сохранялись, дистанция
при завершении равнялась нулю. Foreground service для записи отсутствовал.

## Архитектура

### Модель и расчёты

Добавить независимые от Android и MapLibre модели:

- Состояние записи: готовность, запуск, запись, пауза, прерывание, сохранение,
  ошибка сохранения.
- Состояние GPS и причина недоступности.
- Точка трека: координаты, время получения, точность, номер сегмента и порядок.
- Снимок сессии: идентификатор тренировки, вид спорта, время начала, активная
  длительность, дистанция и статус.

Расчёт дистанции выполняется между принятыми соседними точками одного сегмента.
Точки на паузе, устаревшие и некорректные координаты, недостаточно точные
измерения и физически неправдоподобные скачки не увеличивают дистанцию.
Правила качества GPS и обнаружения потери сигнала задаются централизованно и
проверяются тестами; значения требуют проверки на реальном устройстве.

Активная длительность рассчитывается по монотонному времени. Обновление UI раз
в секунду только отображает её, а не служит источником времени. Пауза исключается
из расчёта. Во время потери GPS длительность продолжает расти.

### GPS

Источник координат для записи не зависит от MapLibre, загрузки стиля и наличия
карты. Предпочтительный вариант — платформенный LocationManager за интерфейсом
источника координат, чтобы основной сценарий не требовал Google Play Services.
Это не требует одновременно менять существующий провайдер отображения карты.

До старта UI различает:

- Нет разрешения на геопозицию.
- Доступна только приблизительная геопозиция.
- Системная геолокация или GPS-провайдер выключены / отсутствуют.
- Поиск подходящей GPS-точки.
- Недостаточная точность.
- GPS готов.

Готовность определяется свежей подходящей точкой, а не только наличием любого
последнего местоположения. При старте и продолжении условие проверяется повторно.
Нельзя начать запись по устаревшей координате из кэша.

При потере сигнала, отключении GPS или отзыве разрешения во время записи UI
показывает причину. Длительность продолжается, расстояние не достраивается по
прямой. После восстановления координат начинается новый сегмент.

### Владелец записи и Android service

Location foreground service владеет активной записью и подпиской на координаты.
Команды сериализуются: два быстрых нажатия не создают две сессии и не сохраняют
две итоговые тренировки.

Сервис запускается из видимого приложения после проверки разрешений и GPS.
Добавить разрешения FOREGROUND_SERVICE и FOREGROUND_SERVICE_LOCATION, объявить
тип location. Для уведомления учесть POST_NOTIFICATIONS на поддерживаемых версиях
Android. Разрешение на постоянную фоновую геопозицию не запрашивать для сценария
запуска из видимого приложения.

Уведомление показывает запись или паузу и предоставляет:

- Пауза / продолжение.
- Открытие экрана записи.

Завершение доступно только из приложения. Если GPS не готов, продолжение из
уведомления не запускает запись: уведомление направляет пользователя в приложение
для проверки состояния. Отказ в уведомлениях не препятствует самому foreground
service, но управление в таком случае остаётся в приложении.

MapViewModel наблюдает общую сессию и отправляет команды. Уход со вкладки,
пересоздание экрана и уничтожение ViewModel не завершают тренировку. Контроллеры
камеры, жестов и отрисовки остаются в UI.

### Локальное хранение

Расширить схему Room с сохранением существующих тренировок:

- Итоговые данные тренировки и признак завершённости; старые строки считать
  завершёнными.
- Единственная незавершённая сессия, связанная с тренировкой.
- Точки трека, связанные с тренировкой: порядок, сегмент, координаты, время,
  точность.

История показывает только завершённые тренировки. Незавершённая запись доступна
через сценарий восстановления, а не как готовый результат.

Принятые точки, дистанция и контрольная точка сессии сохраняются транзакционно.
Длительность сохраняется также периодически и на переходах состояния, даже если
GPS-точки временно не поступают. При паузе фиксируется её начало; при продолжении
создаётся новый сегмент.

Завершение обновляет итоговые показатели, помечает тренировку завершённой и
удаляет незавершённую сессию в одной транзакции. GPS-точки уже связаны с этой
тренировкой: завершение не требует копирования всего трека. Повтор завершения
идемпотентен и не создаёт дубликат.

При ошибке завершения сохраняется остановленный снимок сессии и возможность
повторить ту же операцию. Если само хранилище перестало принимать любые записи,
в текущем процессе удерживается снимок, а после сбоя можно восстановить только
данные последней успешной транзакции. Не полагаться на onDestroy для сохранения.

После аварийного завершения или перезагрузки незавершённая запись открывается как
прерванная. Предлагаются «Продолжить» и «Завершить». Автоматически возобновлять
сервис не нужно. Используется последняя сохранённая активная длительность;
промежуток отсутствия процесса не вычисляется по настенным часам и не добавляется
в тренировку.

## Этапы реализации

1. **Модель сессии и расчёты.** Состояния, команды, монотонная длительность,
   сегментация, фильтрация GPS и расчёт дистанции. Детерминированные unit-тесты.
2. **Хранение.** Новая схема, миграция v1, транзакционные операции для старта,
   точек, паузы, контрольных точек и завершения. Проверка миграции и дубликатов.
3. **Фоновая запись.** Платформенный источник GPS, сервис, разрешения,
   уведомление, обработка ошибок запуска и независимость от экрана карты.
4. **UI записи и восстановления.** Подключение MapViewModel к общей сессии,
   готовность GPS, реальные время и дистанция, ошибки, повтор сохранения,
   продолжение или завершение прерванной записи.
5. **Проверка полного сценария.** Сборка и lint, тесты хранения и переходов,
   проверки на Android-устройстве с выключенным экраном и без интернета.

Не включать в эти этапы несвязанные обновления зависимостей. Если для тестов
миграции потребуется Room testing, добавить зависимость через version catalog с
той же версией Room, что используется в приложении.

## Критерии готовности

- Без точного разрешения, включённого GPS и свежей подходящей точки старт
  недоступен, причина видна пользователю.
- Запись работает без интернета, даже если карта не загрузилась.
- При блокировке экрана и переключении вкладок точки и длительность продолжают
  сохраняться; управление из уведомления работает при разрешённых уведомлениях.
- Пауза исключает время и перемещение; после продолжения нет линии и дистанции
  через паузу.
- Потеря GPS видна в UI; время продолжается, расстояние через разрыв не считается.
- После завершения история содержит одну тренировку с реальной измеренной
  дистанцией, а её упорядоченный трек хранится локально.
- При ошибке сохранения запись остаётся остановленной, доступны сообщение и
  повтор; после успеха появляется ровно одна итоговая тренировка.
- После сбоя и перезагрузки доступна последняя сохранённая сессия с выбором
  продолжить или завершить; промежуток прерывания исключается.
- Существующие тренировки переживают миграцию без потери данных.
- Превью не запускают GPS, сервис или базу данных.

## Проверки

Unit-тесты: время с паузами и задержанными обновлениями UI, фильтрация координат,
дистанция внутри сегмента, разрывы GPS, восстановление, быстрые повторные команды,
ошибка завершения и повторное сохранение. Coroutine-тесты используют виртуальное
время, без реальных задержек.

Тесты базы: миграция существующей схемы, порядок точек, атомарность обновлений,
единственность активной сессии, скрытие незавершённых записей из истории,
идемпотентное завершение и восстановление.

Проверки устройства: реальный маршрут с заблокированным экраном, отсутствие сети,
пауза с перемещением, отключение GPS, отзыв разрешения, отказ в уведомлениях,
прерывание процесса и перезагрузка. Эмулятор подходит для управляемых сценариев,
но не заменяет проверку GPS и энергосбережения на телефоне.

Gradle: :app:compileDebugKotlin, :app:testDebugUnitTest, :app:assembleDebug,
:app:lintDebug; инструментальные тесты базы и UI — на доступном устройстве.
Существующие предупреждения lint учитывать отдельно; новые не подавлять.

## Результат реализации и проверки

Реализованы независимый движок записи, платформенный GPS, location foreground
service с уведомлением, транзакционное хранение с миграцией Room v1 → v2 и UI
готовности, паузы, восстановления и повторного сохранения. История показывает
завершённые тренировки с измеренной дистанцией; точки и сегменты остаются локально.
GPS-база исключена из автоматического облачного резервного копирования Android.

Проверки от 2026-10-05:

- 44 JVM-теста: расчёты времени и расстояния, качество GPS, непрерывность при
  стоянии на месте, команды, восстановление, ошибки хранения и ViewModel.
- 8 Android-тестов на API 32: миграция, атомарность, сохранение и восстановление
  базы, идемпотентность завершения, состояния панели записи и существующий smoke-тест.
- Выполнены :app:compileDebugKotlin, :app:testDebugUnitTest, :app:assembleDebug,
  :app:lintDebug и :app:connectedDebugAndroidTest. Ошибок lint нет; остаются
  15 прежних предупреждений, новые предупреждения не добавлены и не подавлены.
- На эмуляторе проверены запись с выключенным экраном, отсутствие сети, исключение
  перемещения и времени паузы, пауза и продолжение из уведомления, открытие
  приложения из уведомления, восстановление после остановки процесса и завершение
  без подтверждения с появлением результата в истории.

Реальный маршрут, особенности энергосбережения производителей, перезагрузка
телефона и диалог разрешения уведомлений Android 13+ пока не проверены на устройстве.
Подробный просмотр сохранённого маршрута остаётся отдельной следующей фичей.
